# mword 产品方案与第一版范围

日期：2026-10-09

状态：核心产品方向与第一版交付范围已确认；首版正在实现与联调，验证结果见 `VALIDATION.md`。尚未部署到正式服务器或进行手机真机验收。

## 1. 产品目标与优先级

mword 帮助用户理解并记住英语词汇，逐步提升对真实英文文章的阅读能力。

优先把难词讲清楚、帮助记住，再让文章尽可能贴合兴趣。先给本人安卓手机和妻子的 iPhone 使用，后续考虑公开发布。

“无障碍阅读”作为长期目标，按用户选择的内容领域逐步验证，不以完成某个词书直接宣称已经达到。

## 2. 已确认的产品方向

- 保留“先读文章，再学习其中的单词”的主流程。
- 用户选择词书、阅读目标和兴趣，也可以自由输入兴趣描述。
- 通过选项、短文试读和少量练习了解起点；AI 可以帮助调整内容，实际阅读与答题表现持续校准难度。
- 学习记录区分用户，各自维护兴趣、学习进度与复习安排。
- 用户通过服务端账号登录，跨设备同步属于第一版完整交付范围。
- Web、Android 和 iOS 同时交付同一条学习流程。
- AI 的供应商、模型和 Key 由服务器维护；用户无需填写 Key 或选择模型。
- 第一版提供 AI 用量记录和额度管理，实际充值支付后续接入。
- 单词学习围绕本文义项、搭配和用户实际困难展开。
- 默认先提供简明讲解，必要时逐层展开；每次选择一到两种合适的记忆方法。
- 默认回忆方式是先在心里回答，再揭示答案；穿插少量新句理解题，输入短答案作为可选方向。
- 当天理解、延迟回忆和新语境理解分别记录，自评“会了”不直接等同于已经掌握。

第一版提供可选择的预设词库：大学英语四级、大学英语六级、考研词汇。用户选择学习范围，具体词表、释义、例句来源及版本由实施阶段核对并记录。AI 专题词包作为后续扩展，“AI 3000 词”的具体内容和数量需要另行整理。

## 3. 每日学习流程

1. 本地学习系统结合到期复习、薄弱词、词书进度和时间预算安排本次学习。
2. 用户阅读一篇符合当前难度的文章，点击卡住的词或句子。
3. 展示本文词义、发音、原句解释和必要搭配。
4. 需要进一步帮助时，用户选择“还是不懂”“容易混淆”或“帮我记住”，AI 提供针对性解释或记忆辅助。
5. 隐藏解释后主动回忆，再用未见过的句子检查理解。
6. 根据实际练习记录安排后续复习，并在其他文章中再次接触相应词汇。

用户可以直接进入复习。文章不需要容纳所有到期词；不适合主题的词使用单独练习，避免为了覆盖目标词牺牲文章自然程度。

## 4. AI 的职责

| 能力 | 第一版用途 | 质量边界 |
| --- | --- | --- |
| 难词讲解 | 解释本文义项、搭配、句子和易混点 | 以可靠词典依据约束，允许用户报告或纠正问题 |
| 记忆辅助 | 按具体困难提供联想、对比和新例句 | 创作联想明确标注；真实词源有可靠来源才展示 |
| 新语境练习 | 在其他句子中再次练习目标义项 | 检查题目、答案与义项一致性，AI 评价仅作为辅助反馈 |
| 兴趣文章 | 将本次目标词放入自然、可理解的文章 | 检查实际出现、词形、目标义项和整体难度 |
| 难度辅助 | 根据试读与练习帮助选择下一篇文章 | 输出阅读难度建议，不声称给出精确词汇量或标准化等级 |

学习记录、复习排期和进度计算由学习系统负责，不能随 AI 的回答直接改变。AI 的困难诊断是建议，不是对用户能力的确定结论。

新内容生成和动态讲解需要联网；结果保存后可以离线使用。AI 不可用时，缓存文章、内置样文、词典资料和本地复习仍可工作。用户粘贴的文章可用于阅读，本地资料不足时动态讲解仍需联网。

所有模型调用经过 mword 后端。用户请求表达学习场景，例如难词讲解、记忆辅助、新语境练习或文章生成；后端选择启用的供应商与模型、执行内容检查并保存结果。用户端展示 AI 功能、任务状态和额度消耗，不展示模型配置或 Key。

新生成内容采用服务端任务，手机或浏览器离开页面后可以取回结果。初期可通过查询任务状态获取结果，任务需要持久化、受控并发、超时与重试处理。

额度不足时仍允许访问已取得的内容和进行基础复习。缓存讲解再次打开时不重新调用模型，也不再次消耗额度。

暂缓通用聊天机器人、自动全网采编、语音评分和完整词源知识库。

## 5. 词库与文章安排

- 对未掌握目标词提供有计划的学习机会，重复次数根据遗忘和练习表现调整。
- 文章难度考虑所有陌生词，不只检查选定词书中的目标词。
- 同一词出现在不同词书时复用相应学习记录；不同义项分别记录。
- 支持词形变化、常见搭配和短语，避免仅按字符串出现次数计算覆盖。
- AI 文章标注生成来源；真实文章保留来源；改写内容与原文明确区分。
- 词表、释义、音频和例句在选源时核对使用许可。

## 7. 当前技术方向

- 前端：React + TypeScript + Vite + Tailwind CSS。
- 移动端：Capacitor，分别构建 Android 和 iOS 安装包。
- 手机存储：SQLite 保存词库、缓存文章、学习记录与待同步数据；登录凭证使用系统安全存储，手机不保存模型 Key。
- Web 存储：IndexedDB 保存本地缓存和待同步记录，使用独立的 mword 数据空间并按账号隔离；已同步记录由服务端持久保存。
- 后端：Spring Boot + MyBatis-Plus + MySQL，先按业务模块组织一个应用。
- 服务端 AI：参考 merchant-copilot 的通用配置和调用结构，增加学习场景路由、内容验证、任务管理与额度账本。
- 复习：首版采用客户端、服务端一致的确定性 `interval-v1` 调度，记录规则版本并独立保存事件；后续依据实际学习数据评估 FSRS。
- 朗读、通知、SQLite 和安全存储插件需要核对兼容性并进行两端真机验证。

手机与 Web 使用统一的学习和同步接口，通过存储适配分别访问 SQLite 与 IndexedDB。浏览器缓存可能被清理，已上传到服务端的学习记录可在登录后恢复；未上传记录不能承诺在本地存储被清理后恢复。

登录、同步与额度规则见下节，联网不是已缓存内容阅读与基础复习的前提。

## 9. 登录与跨设备同步的实现约定

- Web、Android 和 iOS 通过同一套 mword 服务端账号登录。账号密码作为初期实现建议，注册与账号维护的具体交互在页面设计时明确。
- 首次登录需要联网；已登录用户可以离线使用已缓存内容与基础复习，恢复网络和有效会话后补同步。
- 服务端 MySQL 保存已同步学习事件及统一学习状态；客户端及时记录操作，并维护未确认的上传队列。
- 同步范围包括词书选择、兴趣与学习设置、文章和已取得的讲解、阅读进度、学习事件及复习安排。
- 每次学习事件记录唯一编号、账号、设备、目标词与义项、发生时间、练习类型、提示使用情况和结果。不同类型的练习分别记录，不能把阅读曝光当作成功回忆。
- 同步按事件增量上传、按服务端游标增量拉取。重复上传同一事件不重复计入，不同设备真实发生的两次学习都保留。
- 合并后统一计算学习状态，避免设备以最终熟练度互相覆盖。客户端与服务端采用同一版本的复习规则，并验证跨端一致性。
- 设备时间偏差、迟到事件、事件排序及参数版本在同步协议中明确，不能直接信任设备时间或只按上传顺序推导复习结果。
- 启动、恢复前台、完成学习和网络恢复时尝试同步；失败保留队列并提供重试，界面展示待同步数量和最后成功时间。
- 切换账号时隔离缓存和待同步队列；账号 A 的记录不能上传到账号 B。
- 词库使用版本标识与稳定词、义项编号，更新词库或切换词书时保持已有学习记录。

## 10. AI 用量与额度管理的实现约定

已确认第一版交付用量记录与额度管理，实际充值支付后续接入。初期由后台分配或调整额度。

- 用户看到各类 AI 功能的预计消耗、剩余额度和使用记录；具体额度单位、默认分配值及各场景消耗在实施阶段配置，不在当前文档中虚设金额。
- 后台按学习场景选择模型，Key 仅在服务器维护并受后台管理权限控制，不返回给学习端或写入客户端资源。
- 按用户校验额度，并使用唯一请求编号防止重复创建任务或重复消耗额度。
- 推荐先预占额度，生成结果通过内容检查并保存成功后结算；失败、取消或未产生可用结果时释放预占额度。任务恢复和超时清理需要明确最终状态。
- 用户额度变动与模型调用日志分别保存。调用日志记录输入输出 Token、耗时、模型和结果状态；Token 日志本身不等同于用户额度账本。
- 同一账号跨设备共享服务端余额。额度校验与变动在服务端执行，客户端缓存余额仅用于展示。
- 已生成且仍可访问的内容重复打开不消耗额度；主动重新生成属于新请求，应事先展示消耗。
- AI 超时、失败和额度不足有明确状态，保留原有内容与学习进度，并提供合适的重试入口。

## 11. 实施细节与验证顺序

用户此前列出的五项范围已明确，不再保留自填 Key 或推迟跨设备同步的方案。词库内容来源、模型路由、具体额度参数、服务器端口、依赖版本、原生插件与视觉风格属于后续实施细节；实际充值支付属于后续范围。

1. 据已确认范围设计登录、词库选择、阅读、单词讲解和复习的页面交互，以及存储、同步与额度接口。
2. 在两台真机验证点击查词、选文、朗读、SQLite 断网读写、通知、键盘、安全区和后台恢复。
3. 开发阶段先用一套词库打通完整流程，再完成考研、四级、六级三套预设词库的交付与质量检查。
4. 完成登录、跨设备事件补传与全量拉取、AI 内容检查、额度管理与故障恢复，联合验证 Web 和两部手机；后续按真实规模扩展增量拉取。
5. 连续试用，观察每日负担、复习积压、延迟回忆和陌生句子理解。
6. 完成同步、部署与发布检查，同时交付 Web、Android 和 iOS；后续再扩大词库和用户范围。

验收关注：

- 无提示时，隔几天能否回忆目标义项。
- 换一个句子后，能否理解相应意思。
- 难度相近的陌生文章中，理解表现与查词次数的变化。
- AI 是否遗漏目标词、误用义项或生成错误解释。
- 断网、AI 失败、app 重启和重复同步后，已完成的学习记录是否保留。
- 同一账号在 Web 和手机上切换、两个设备离线学习后同步、凭证失效再登录时，记录是否正确合并。
- 三套预设词库可选择，重叠词复用同一用户的相应学习记录，词库版本更新不重置进度。
- 同一 AI 请求重试和并发提交时不重复消耗额度，失败能释放预占，已缓存内容可继续使用。
- 学习端不存在供应商选择、自填 Key 或可返回服务端 Key 的接口。

“看过多少单词”只作为活动记录，不作为记住或阅读能力提升的证明。
